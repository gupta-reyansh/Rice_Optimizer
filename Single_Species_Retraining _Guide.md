# Technical Guide to Retraining and Model Outputs for a Single Species

---

## 1. Overview of the Current Training Logic

The formal input for single-species retraining is not a FASTA file, but two intermediate outputs:

1. **Training CSV**: Contains the columns `dna`, `protein`, and `organism`.
2. **Training JSONL**: Generated by `CodonTransformer.CodonData.prepare_training_data(...)` and read by `pretrain.py`.

The current one-command script performs the following process:

1. `read_fasta_file(...)` reads the FASTA file using Biopython and translates the protein sequences using the specified or inferred codon table.
2. Records that cannot be translated correctly or have invalid lengths are filtered out, unless retention is explicitly requested.
3. A training CSV is generated.
4. `prepare_training_data(...)` generates the training JSONL and maps the current species to the local organism ID `0` for this training run.
5. `pretrain.py` initializes a BigBird masked language model from scratch and begins training.

Unlike the previous single-species fine-tuning process, the current one-command script uses all qualified CDS records after filtering by default. It no longer performs CSI Top 10% subset selection intended for fine-tuning scenarios.

## 2. Environment Setup

### 2.1 Basic Software Requirements

- Python `>=3.9`
- `pip`
- An available CUDA / GPU training environment (`pretrain.py` currently requires GPU acceleration)
- If a local tokenizer file is not provided, network access to the Hugging Face tokenizer repository

### 2.2 Recommended Setup

Run the following commands:

```bash

python -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip setuptools wheel
pip install -r requirements.txt

```

## 3. Input Data Requirements

### 3.1 Input File Type

The one-command training script accepts a **CDS FASTA** file as its raw input. Each record should represent a gene-level CDS rather than an entire chromosome, contig, or scaffold.

### 3.2 Sequence Quality Requirements

The input data should ideally meet the following requirements:

1. DNA sequences should use uppercase letters and contain only `A/T/C/G`.
2. Sequence lengths should be multiples of 3.
3. Sequences should ideally begin with a valid start codon and end with a stop codon.
4. The dataset should avoid internal abnormal stop codons, low-quality annotations, and obvious assembly errors whenever possible.
5. If the FASTA file contains many incomplete or incorrectly translated sequences, clean the data before training.



## 4. One-Command Retraining Script

This script performs the following steps:

1. Reads the CDS FASTA file.
2. Translates the protein sequences using the specified or inferred codon table.
3. Filters records with `correct_seq=False` by default.
4. Generates the training CSV.
5. Generates the training JSONL.
6. Calls `pretrain.py` to start training from scratch.
7. Saves intermediate files, training metadata, and checkpoints in the working directory.

### 4.1 Minimal Command

```bash
cd /home/runner/work/CodonTransformer/CodonTransformer

python train_species_model.py \
  --input_fasta "/absolute/path/to/species_cds.fasta" \
  --organism "Oryza sativa" \
  --codon_table 1
```

With this usage, the script automatically creates the default working directory:

### 4.2 Common Command

```bash

python train_species_model.py \
  --input_fasta "/absolute/path/to/species_cds.fasta" \
  --organism "Oryza sativa" \
  --work_dir "/absolute/path/to/workflows/Oryza_sativa_run01" \
  --codon_table 1 \
  --batch_size 1 \
  --max_epochs 5 \
  --num_workers 5 \
  --num_gpus 1 \
  --learning_rate 5e-5 \
  --warmup_fraction 0.1 \
  --save_interval 5 \
  --seed 123
```

### 4.3 Retaining Records with `correct_seq=False`

```bash
python train_species_model.py \
  --input_fasta "/absolute/path/to/species_cds.fasta" \
  --organism "Oryza sativa" \
  --codon_table 1 \
  --keep_all_records
```

> Enable `--keep_all_records` only if you clearly understand the risks associated with data quality.

### 4.4 Script Parameter Description

| Parameter | Description | Default |
|---|---|---|
| `--input_fasta` | Path to the CDS FASTA file | Required |
| `--organism` | Target species name, mapped to the local organism ID `0` for this training run | Required |
| `--work_dir` | Working directory | `<repo_root>/workflows/<organism_slug>` |
| `--tokenizer_path` | Path to a local `tokenizer.json`; loads the default Hugging Face tokenizer when empty | Empty |
| `--codon_table` | NCBI codon table used to translate the FASTA file | Automatically inferred |
| `--keep_all_records` | Whether to retain records with `correct_seq=False` | Disabled |
| `--batch_size` | Training batch size | `1` |
| `--max_epochs` | Number of training epochs | `5` |
| `--num_workers` | Number of DataLoader workers | `5` |
| `--accumulate_grad_batches` | Number of gradient accumulation steps | `6` |
| `--num_gpus` | Number of GPUs to use | `1` |
| `--learning_rate` | Learning rate | `5e-5` |
| `--warmup_fraction` | Warmup proportion | `0.1` |
| `--save_interval` | Checkpoint-saving interval in epochs | `5` |
| `--seed` | Random seed | `123` |
| `--debug` | Debug mode passed through to `pretrain.py` | Disabled |

## 5. One-Command Script Output Structure

By default, the working directory will contain the following:

```text
<work_dir>/
├── checkpoints/
│   └── epoch_*.ckpt
├── data/
│   ├── processed/
│   │   └── training_data.json
│   └── raw/
│       ├── parsed_cds_records.csv
│       └── training_sequences.csv
├── logs/
└── run_metadata.json
```

The files have the following meanings:

- `parsed_cds_records.csv`: Raw records parsed from the FASTA file, including translation results and the `correct_seq` flag.
- `training_sequences.csv`: The final three-column table used for retraining (`dna/protein/organism`).
- `training_data.json`: JSONL training data read by `pretrain.py`.

> For single-GPU environments with limited VRAM, keep the default `--batch_size 1 --accumulate_grad_batches 6`. This can significantly reduce peak VRAM usage while maintaining an effective batch size close to the previous default.

- `run_metadata.json`: Parameters, species name, local organism ID, and sample-size summary for the run.
- `checkpoints/`: Output directory for the retrained model checkpoints.

## 6. Common Troubleshooting

### 6.1 Leading or Trailing Spaces in `--organism`

The script automatically applies `strip()` to `--organism`. For example:

```bash
--organism "Oryza sativa "
```

is normalized to:

```text
Oryza sativa
```

### 6.2 Incorrect Translation Results for a New Species

If the target species is not accurately covered by the built-in codon table inference rules, explicitly specify:

```bash
--codon_table 1
```

or another correct NCBI codon table number.

### 6.3 Tests Failing Before Training

The repository's existing tests depend on packages such as `pandas`, `torch`, and `ipywidgets`. If the tests fail during import, install requirements.txt

### 6.4 No GPU Available

The current `pretrain.py` uses a GPU trainer configuration. If no GPU is available, the underlying training script must be adjusted before CPU training can be performed.
